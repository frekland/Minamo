# Terminal evidence inside Notes

The existing owner-scoped Note and `markdown-v1` body remain authoritative. A deliberately inserted capture is one standalone `[[minamo-terminal:v1:{JSON}]]` line. The JSON has `id`, exact `output`, and optional `label`, `command` and `environment`. JSON escaping keeps actual newlines, carriage returns, tabs, Unicode, controls, Markdown fences and image-like source inside the payload. A capture is not a Run and implies no execution, authenticity, interpretation or learning achievement.

The rich codec parses the marker as an atomic ProseMirror node. The saved reader parses the same marker as a terminal block with deterministic visible-text coordinates. Prose stays around and between captures. Identity and output survive rich edits, undo, serialization, exact Note revisions and normal guarded saves. Captures in fenced code examples remain literal code. Duplicate identities or malformed markers fail shared validation. The extension adds no domain family, database table, hidden conversation ingestion or independent write queue.

Both writing and reading start compact, with expansion, bounded internal scrolling and copy. Writing additionally provides edit, remove and continue-writing controls. Escape/control and bidi-control characters are displayed as visible `\uNNNN` text; CRLF displays as LF and isolated CR as `␍`. The original output remains exact in source, server reads and Copy output. Text is rendered as text, never HTML, ANSI instructions or commands. Optional command/environment labels are descriptive.

The Insert terminal output dialog preserves its pending paste locally under the originating owner scope and Note identity when closed or rejected. It never truncates pasted output. The entire encoded Note still has the existing 24,000-character bound; an over-limit insertion remains in the dialog with guidance to select a smaller excerpt or attach a text file. Identity checks prevent insertion into a different Note. The generic rich-edit limit also keeps a rejected attempted source available for copying. No autosave command is issued for rejected insertion.

GPT authors the same representation through the shared `data.noteContent` ordered markdown/terminal blocks, compiled into `body` with `bodyFormat:'markdown-v1'`. Prediction, observation, interpretation and uncertainty belong in the separate supplied prose; the compiler invents none of them. Routine tutor context can use compact capture headers and exact Note/capture references; an exact Note rendition retains all output. Installed-client availability must be checked after an explicitly approved release.

`tests/note-terminal.test.mjs` checks exact and displayed bytes, caret insertion, mixed prose/captures/images, revision-compatible round trips, undo/replacement, typed input interoperability, invalid/over-limit input and compact follow-up pointers. `/preview-notes` is a development-only actual-component fixture with a terminal case and the saved reading representation. It makes no claim of a production save or device acceptance.

The additional `/preview-growth` development fixture uses actual local D1 and a fixed `TEST-ONLY-growth-browser-principal`, with deliberate web saves/reopening, retained renditions and a JSON-RPC typed-capture creation/readback. Its Classic/Focus/Task controls keep the same editor memory while changing the fixture presentation label; they are not a substitute for the full production layout integration. A 390px constrained fixture exercises narrow presentation. `tests/growth-preview.test.mjs` verifies persistence, retained reading, typed-capture interoperability and the production `DEV=false` 404 boundary. The proxy exists only under a compile-time development branch and never supplies identity to the production API. Existing production authentication is unchanged.

Independent review exposed and corrected source-caret coordinate confusion, an info-bearing fence misclassified as a closer, a stale end-of-Note Continue writing position, and cancelled replacement text being replaced by the older saved capture on reopening. Continuing after a terminal now resolves its identity in the current transaction and ensures an in-range trailing paragraph. Pending replacements retain their capture id across source/rich mode; source replacement updates the exact marker rather than inserting a duplicate. Pending drafts are stored per capture identity, so switching between captures cannot overwrite another retained paste.
