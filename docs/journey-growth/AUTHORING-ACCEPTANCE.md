# Goal-first authoring and local-work acceptance

Synthetic isolated Worker/MCP/D1 checks on 25 October 2026. Production and genuine learner content were not used or modified. This is development-server acceptance; installed-client catalogue refresh and private hosted acceptance remain release checks.

## Product changes

The current editorial contract makes occasional new-Journey creation explicitly thorough: inspect exact existing coverage, anticipate prerequisites and likely future mechanisms, research changing facts, prepare reusable Library depth and connected open questions, then give a concrete practical entry point. Optional reading stays independent of mandatory stages. A need for new knowledge can extend the collection without replacing existing work.

An explicit `Start working locally` or `Try this in your environment` Journey heading is discoverable through `journeyLocalStart`. It requires one unambiguous authored stage with eligible content. It supplies an exact stage destination and labels the material as external guidance, never observed execution. It does not infer starters from arbitrary prose or treat a code block as a runtime.

Manuscript shape errors now name the unsupported field, allowed fields and safe retry boundary. Text-limit errors identify the field, supplied count, maximum and units without echoing input. Full submitted source stays in the caller's unchanged request; no source is silently repaired, truncated or committed on rejection.

A lifecycle check found an actual recovery defect: after a targeted manuscript replacement committed, identical retry checked the necessarily stale old target revision before the shared operation replay lookup. Publication now compares the exact immutable request hash under the generation fence before target compilation and recovers a concurrent committed operation. Changed input still rejects, stale new operations still fail, and previous editions remain readable.

The lifecycle verifies coherent publication, direct local-stage destinations, exact copied Rust/HTML source, read-only reuse, a later extension, old readings, CAS, immutable-operation recovery, unsupported-field guidance, an intact rejected 24,001-character brief and a rejected 17-document atomic request. Two initial goal publications need two actual publish calls and zero required previews. These are authoring-path counts after coverage is inspected, not measured human time or a claim that atomic bulk publishing itself is new.

Before, unsupported manuscript fields produced a generic shape error and an over-limit brief produced a generic bounded-text error. After, each exposes its exact field and repair boundary in the first rejection. Before, an identical retry of a committed targeted replacement reported `coverage_changed`; after, it returns the original committed receipt with `replayed:true`, without another revision or record. Initial depth is judged by coherence, technical accuracy and local actionability, not by minimising research/authoring effort.

The exact game's rules and event paths were independently executed under a Node VM with synthetic DOM/event stubs; this does not establish browser rendering or physical device behavior. Parent browser acceptance records the separate real UI result. Rust/Cargo are absent: the complete Rust starter remains uncompiled and Rust execution is unverified. No Python substitute or manually calculated counts are described as compilation evidence.
