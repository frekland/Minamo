# V2 security and evidence boundaries

This documents implemented boundaries, not a claim of complete parity with original Minamo.

## Implemented

- Hosted visitor identity is supplied by Sites dispatch. API reads/writes and MCP record invocation require both Site-scoped user ID and email; there is no app-owned login or credential impersonation. The private Site access policy is an independent platform boundary. Tests inject synthetic headers only at a local boundary; they do not prove hosted identity behaviour.
- Shared server domain validation owns create/update/Trash/restore, explicit links, article parts and exact anchors. UI validation is convenience only. User payloads cannot set server actor, revision, timestamps or receipt identity fields. Data and revisions are selected with owner predicates.
- Mutation batches include operation-ID reservation, nonce ownership, CAS, revision history, activity and acknowledgement. Reusing an operation with another payload is rejected. Concurrent identical operations commit one revision/activity; concurrent stale edits cannot overwrite newer work. Operation status/replays return metadata and record references, not retained content bodies; eligible record reads remain a separate step.
- Exact capture uses immutable, family-qualified retained reading identity plus section/part UTF-16 offsets and an exact quote. The nine readable families are Journey, Investigation, article, area, Note, Annotation, Source, Experiment and Run; Run code/output are literal canonical parts. `anchor.recordFamily` is explicit for new captures, while legacy `articleId`-only captures retain their article meaning. Old renditions stay readable only while the same owner/family/ID current record remains active. A changed record does not relocate old captures by title/text matching. Personal capture prose survives when its target is unavailable. Existing annotation/Flag origins cannot silently be retargeted.
- Collection and literal-query reads have bounded UTF-8 pages and deterministic keyset continuation across timestamp ties. Cursor scope binds principal, read kind, filters and page size; each continuation independently applies owner/eligibility predicates. Cursors are continuation state, not signed authority or a stable snapshot. Exact selected records and saved capture references are read independently of collection pages. A record absent from a loaded page does not authorise deletion, draft loss or recreation. MCP validates its exported 1–40 page limit before computing continuation.
- Structured tables retain exact canonical TSV, with displayed cells mapped to stored UTF-16 offsets. Callouts and reference cards retain authored text; reference metadata admits only safe HTTPS link-only pointers and never fetches or embeds remote material. Semantic links preserve purpose and pin exact destination families, renditions and parts; new or changed destinations and Source references are checked against owned active records and guarded in the mutation batch.
- GPT handoff is an explicit clipboard read request containing only identity, rendition and coordinates. It does not invoke a tool or command automatically, and does not put Note prose, titles or quoted passages in URLs. Context selection text is derived by the server from an eligible pinned rendition; selected related identities remain independently owner-fenced. Annotation reading and original captured-passage return links remain distinct.
- Source admission currently accepts original authored material and HTTPS link-only source metadata. Imported third-party excerpts are rejected because a rights/admission lifecycle has not been implemented. A source URL is not a copying grant. This is intentionally narrower than original Minamo's source-policy machinery.
- A GPT command cannot change a non-synthetic observed Run into fabricated observed evidence by omitting evidence fields from an update. Activity actor/channel and synthetic classification stay explicit; a successful save is not proof of learning.
- Tools use bounded isolated execution: RegExp and in-memory SQLite in terminable Workers; Python in a sandboxed opaque-origin frame and Worker with network-denying CSP; Web uses an admitted finite HTML/CSS surface and fixed event handler, not arbitrary JavaScript. Tool state belongs to the browser runtime, separate from durable Runs. Web is not claimed as a general hostile-code CPU sandbox. SQLite is a temporary tool database, never app D1.

## Independent regression evidence

`tests/security-boundaries.test.mjs` exercises actual domain code and local Miniflare D1, without mocked storage. It checks schema rejection, concurrent identical idempotency, payload mismatch, private metadata receipts, cross-owner status isolation, Trash fencing, genuine-observation guard, source protocol/admission rejection, contiguous multi-part canonical joins, title/introduction/heading targets, surrogate-pair UTF-16 capture, immutable anchors and retained revision/unavailable-source behaviour. `tests/security-generic-reading.test.mjs` separately exercises all eight readable families, same-ID cross-family collisions, legacy article anchors, literal CRLF Run code/output, generic retained editions, source Trash eligibility, and read-only legacy history projections for pre-generalisation records without stored rendition IDs. `tests/security-pagination.test.mjs` independently exercises owner/filter/page-size cursor binding, malformed cursor rejection, timestamp ties, post-page Trash fencing, authenticated exact reads beyond the first page, UTF-8 byte-budget continuation and MCP page-limit rejection. `tests/security-rich-content.test.mjs` exercises actual D1 rich-text roundtrips, table canonical mismatch rejection, reference rights/URL restrictions, semantic destination and Source ownership admission, server-derived selections and related-record isolation, retained rich editions, stale CAS and Trash/restore. Run these suites with the domain HTTP/MCP suite and exact compiled Worker tests before release.

The review caught and corrected a malformed activity INSERT that initially blocked every create, mutable exact annotation origins, content-bearing replay/status receipts and a partial-update bypass of the GPT genuine-observed Run guard. Reader/workspace integration now carries retained rendition identity through exact return, resolves metadata-only acknowledgement recovery before clearing a pending Note, locks unrelated edits while immutable saves are unresolved, and preserves rich article parts during deliberate metadata edits. Mixed-family navigation, capture restoration and retained history are fenced by family plus ID, rather than ID alone. Pre-generalisation history obtains deterministic `legacy-{family}-{id}-r{revision}` projection IDs without rewriting rows on GET. Local source review does not replace the remaining browser acceptance for those paths.

## Not yet full original-product parity

There is no claim of original Minamo's protected archive/generation recovery, permission-controlled imported-source admission/restriction, complete editorial-remit policy, or every old runtime feature. Per-record retained revisions and recoverable Trash are not a complete backup/restore system. Pagination does not freeze a corpus: concurrent updates can move records ahead of an existing cursor; refresh restarts from the current first page. Local contract tests do not establish hosted browser acceptance, mobile/touch accessibility or refreshed ChatGPT client schemas. Release evidence must state which of those were actually exercised.


## Protected recovery continuation

Owner-scoped complete product checkpoints, immutable R2 integrity checks, isolated staging, pre-activation backup and atomic generation/mutation-version fences are implemented in `lib/recovery.ts`, `lib/recovery-handler.ts` and `lib/generations.ts`. Root-scoped current Source/image restriction floors apply across restored history; old namespaces cannot grant broader rights. The portable JSON export is rights-aware and explicitly non-restorable/image-reference-only. See [tested guarantees and remaining limits](RELEASE-PROTECTED-RECOVERY-2026-10-21.md); this continuation supersedes earlier statements that all protected checkpoint/generation recovery was absent.
