## What later GPT/Light work can do

- **Tier 0:** publish new supported Activities and accepted recipe data through the staged typed MCP, with no frontend changes. Existing templates derive a safe default when a recipe is omitted.
- **Tier 1:** enable a prepared trusted view with a bounded registration and select it on an admitted compatible block; inherit rights, exact source, fallback, mobile layout and Notes.
- **Prepared extension:** scaffold a finite supplied-event presentation, register its metadata and static loader, then run generated source/lifecycle/domain/browser fixtures. No Workspace or Notes refactor is needed.

The fresh trials are empirical restricted-context work by the available agent model, not a claim of measured literal Sol Light economics. Initial failures and Pro interventions remain in the reports. New sandbox/domain/device families remain substantial engineering; prepared source/view families no longer require an open-ended layout redesign.
