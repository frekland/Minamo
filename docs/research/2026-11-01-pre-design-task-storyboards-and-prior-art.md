# Divergent task storyboards and observable prior-art mechanisms

**Status: low-fidelity, testable hypotheses — not mock-ups, approved design or functional prototype commission.** Parent [independent audit](2026-11-01-independent-pre-design-audit.md), owner decision [2026-11-01](../PRODUCT-DESIGN-DISCOVERY-DECISION-2026-11-01.md), issue [#51](https://github.com/frekland/Minamo/issues/51). Use **identical tasks and the same evidence set** across four conditions. The prior [PR #75 ledger](2026-11-01-connected-episode-ledger-and-divergent-interactions.md) introduced A/B/C; this extends it to first-screen/actions/interruption/GPT/failure and adds a reductionist counter-hypothesis D.

## Common ground, guardrails and evaluation

- **Current baseline:** Minamo has Project/Stage/Question, Notes, Library Article reading, Practice & review/Activity Studio, exact reader origin/annotation/receipt handling, session task/position data and GPT on selected context. These are useful. Current Stage → Question → Note loses origin; Article reverse Activity hides beneath closed Your work and says Tool. Direct Project related closure is not an exhaustive learner timeline. A learner can already capture an unplanned Note; do not claim they cannot.
- **Four identical tasks:** T1 unplanned Note *before* any Project choice; T2 after gap, newer conflicting intentions versus older checkpoint (Mood K); T3 sparse interrupted work **without** checkpoint (Cap K) or provisional non-technical work (Plant K); T4 Article exact paragraph → existing Activity → capture thinking → return to same source/reading position.
- **Safety/authenticity:** All narrated records are synthetic except generic Article/Activity examples. No live learner record mutations. “Correct” means source-backed and useful without manufacturing learner belief, Stage completion, or successful test. Each approach must support a direct unstructured Note and an accessible return without GPT.
- **Evaluation log per task:** time/steps before meaningful action; wrong or hidden entry; backtracking; exact source/edition and return success; ability to defer linking; consistency of conflicts and unknowns; where effort was spent curating; accessibility keyboard/mobile; rights/partial-data fidelity; whether learner perceives control; what existing Project/Reader/Practice value remains. Have the owner or representative actually perform tasks later; speculative scores are not acceptance evidence.

## T1 — A spontaneous Note with no Project selected

| Condition | First screen, learner actions and source reuse | Interruption, GPT and likely failure |
|---|---|---|
| **Baseline today** | From global Notes/create capture a raw idea in own words. Optional task links are not forced by [lib/note-capture-context.ts](../../lib/note-capture-context.ts). Later locate via Notes/related links; no automatic useful relation to a question. | Closing and returning may leave a disconnected Note. GPT can discuss selected content but its relationship is not authoritative. Failure: search and future re-finding/meaning; **not** inability to create Note. |
| **A. Contextual integration** | Stay on Notes. New Note screen allows “Capture now,” optional “Link to reading / question / project later” and visible originating source if one existed. A quiet Recent Notes surface makes it findable without assigning a Stage. | On interruption, Note remains in chronological/keyword return, no invented Project. GPT may offer *suggested* source associations with quote/accept control. Failure: still many disconnected surfaces and little situated work; suggestion noise. |
| **B. Living inquiry** | First screen is an editable “What am I wondering/trying?” inquiry or a plain Note; choosing inquiry is **optional**, not an initial Project wizard. Capture idea; later place it under one or several revisable inquiries; Stage may appear only as guidance. | Reopening displays question, last sources and unconfirmed next intent. GPT suggests inquiry framing, not a canonical status. Failure: every unplanned thought becomes a forced “episode,” with maintenance and premature framing. |
| **C. Evidence worktable** | First screen a blank field notebook canvas plus quick capture; Note lands as a loose card, not inside a Project. Drag an Article excerpt or prior Note next to it only if useful; multiple notebooks/views can reference one canonical record. | Return opens the same selected evidence/arrangement with source links. GPT can compare chosen cards but not auto-arrange/merge. Failure: manual curation, card sprawl, tiny-screen complexity and confusing duplicate appearances. |
| **D. Capture-first field log (counter-hypothesis)** | One dated free-text entry, source URL or reference optional, no workspace structure. Revisit via activity log/search with a “Link this later?” non-blocking action. | Return shows last authored entry and *no claim* about progress; GPT optional on demand. Failure: may be too weak for dense cross-source reasoning, or recreate Note disconnection with fewer features. |

## T2 — Returning to conflicting intentions and an older checkpoint (Mood K)

Evidence common to all: later learner Note rev 2 on v5/v7 and privacy, a loose-ends Note linking two Questions, an older S03/H checkpoint proposing v6 checks, and incomplete Project-root reachability. Neither learner report nor checkpoint proves a passed v7 reload test.

| Condition | First screen, actions and source reuse | Interruption, GPT and likely failure |
|---|---|---|
| **Baseline today** | Project home/Stage exposes a continuation destination, recent Question Notes and separate older saved learning. Learner opens several surfaces to reconcile v6/v7. Some Notes vanish from root direct-related list despite existing via Question. | Back to Step breaks after Note hop; no single qualified account of conflict. GPT result depends on selected slice. Failure: older formal state appears fresher than later informal work. |
| **A** | Project/Stage shows compact “Since last saved checkpoint” with linked newer Note rev 2, older checkpoint date, and **two** explicit proposed next actions, each with source/uncertainty. Learner chooses which Note to inspect; return preserved through hops. | New evidence refreshes strip read-only; GPT may summarize conflict only from selected sources, with “confirm next” not auto-save. Failure: under-Project context may miss unrelated concerns; strip becomes dashboard overload or falsely authoritative. |
| **B** | Inquiry page “Are personal labels retained privately?” foregrounds revisable intention and recent evidence by Question, not pre-authored Stage number; learner sees competing “v6 verification” and “v7 opt-in test” intents, selects focus, optionally links Project as course map. | Return to inquiry preserves last selected task and unresolved contradiction; GPT drafts a test plan pending confirmation. Failure: creates another persistent intention layer that lags behind spontaneous Notes or confuses authorship. |
| **C** | Worktable opens an evidence board with older checkpoint next to newer rev 2 Note and actual source/test receipts in a comparison lane; learner highlights disagreement and pins one next observation. | Reopen same evidence juxtaposition and edition pins; GPT proposes a comparison, with unknown data visibly absent. Failure: too much arrangement before simple resumption; sparse records look absurd as a board. |
| **D** | Chronological field log shows latest Note, one older explicit checkpoint and two dated “next” snippets with their source links. Learner picks a next action or just resumes writing. | No elaborate model; GPT only on ask. Failure: semantics of revisions/contradictions get buried in chronology when histories become large. |

## T3 — Sparse interrupted lab or provisional non-technical calibration, **no checkpoint**

Use Cap K with changed authorised instance and one harmless observation; repeat Plant K with raw counts/hysteresis and unmeasured dry/wet soil. Do **not** score exploits or physical calibration as completed.

| Condition | First screen, actions and source reuse | Interruption, GPT and likely failure |
|---|---|---|
| **Baseline today** | Enter Project/Stage and Notes; formal saved-checkpoint region empty. Direct Project links may omit recent Question-linked Note. Learner manually finds latest restart or raw-readings revision. | “Start first step” or empty formal progress feels false after thoughtful revision. GPT may lack omitted sources. Failure: equates structured checkpoint with progress. |
| **A** | Open whichever surface user last visited; compact “recent authored work” includes no-checkpoint Note and an *explicit* “No saved checkpoint; other notes may exist” label. Project may be bypassed with a direct Note continuation. | Return via date/source; GPT offers one cautious next observation using visible Note text and coverage. Failure: Project-first UI remains uncomfortable for a lab not following Stage instructions. |
| **B** | Open editable concern “How do I safely re-establish the permitted instance?” or “What would validate a soil threshold?” Learner updates constraints; source Notes and optional Stage directions appear beside concern. | Interrupted concern survives by explicit user pin or read-only link/recent evidence. GPT might help refine inquiry; cannot state a flag, credential or physical result. Failure: synthetic tidy “intent” model makes messy life look like a formal syllabus. |
| **C** | Open field table of latest restart Note plus old instance note, or proposed hysteresis chart beside raw-reading note with “physical validation missing.” Learner annotates uncertainty and selects next observation. | Pinned sources persist as view context; GPT contrasts models, never certifies measurements. Failure: cost of selecting and arranging evidence swamps sparse safe observation. |
| **D** | A dated “return log” shows the last two Notes, raw-text uncertainty, and lightweight source edges; enter next observation directly. | Recovery is chronological, no checkpoint. GPT optional suggestion. Failure: weak for relating many changing experiments, revisions and Articles. |

## T4 — Source Article → Activity → new thinking → exact Article/task return

Common precondition: Article A edition e1, passage anchor p, existing permitted authored Activity X sourced to A, and optional question/project context Q/S. Reproduce same task at narrow mobile width and with keyboard.

| Condition | First screen, actions and source reuse | Interruption, GPT and likely failure |
|---|---|---|
| **Baseline today** | Find Article via Library. Scroll to collapsed bottom Your work; expand and choose Tool, which opens the Activity. Source can be reached from Activity Related content. After Note hop, original context may not be carried. | Return can fall to Practice rather than the exact passage; source/Activity relation exists but is practically hidden. GPT may not get Article anchor. Failure: route and discovery before any new design need. |
| **A** | While reading A at p, a plain named “Activity: practise this source” action appears contextually. Start X; save/select Note with A e1/p/Activity source receipt; choose “Return to passage” and land at p, preserving Q/S if originated there. | Browser and reader position restoration with safe stale-edition/permission fallback; GPT may explain only selected passage. Failure: contextual chrome grows crowded, distracts readers, and still makes multi-source thinking awkward. |
| **B** | Enter Article through current inquiry; Activity offered beside the cited passage; Note and result attach to revisable inquiry **and** exact source (neither requires Project). Return to inquiry or source explicitly. | Inquiry persists with unfinished Activity and source receipt; GPT suggests follow-up question after learner review. Failure: treating every Article exercise as advancement of one inquiry, or duplicating Practice's role. |
| **C** | Add A e1/p clipping to worktable beside X; open X in context, capture Note as new evidence object, return to the source card and its original passage. Worktable may contain competing passages from several Articles. | View persists with exact sources, not copied text without provenance; GPT compares selected excerpts, labels unknown coverage. Failure: heavy drag/drop inaccessible or duplication/edition confusion; exact in-Article flow slower than A. |
| **D** | Article in ordinary Reader with clear existing Activity action; a Note appends to log with source anchor; “Return to passage” goes back to A e1/p. No special worktable. | Recent log + browser/reader restoration; GPT optional. Failure: related cross-Article evidence remains hard to compare without manually reopening many tabs. |

## Comparison and actual rejection rules

These are directional **hypotheses**, not numerical scores inferred from code. Score future observed tasks (0–4 and evidence note) across capture friction, resumption truth, source return, learner control, flexibility without Project, physical/non-technical authenticity, screen-reader/mobile operation, cognitive cost, explicit relationships and real implementation/maintenance risk.

| Criterion | Baseline | A minimal integration | B inquiry | C evidence table | D field log |
|---|---|---|---|---|---|
| Structural commitment | Optional Note but Stage gravitates to centre | Existing surfaces, optional source edges | New revisable intent concept | Selected evidence spatial organisation | Almost none |
| Likely lowest-cost fix to known R1/R2 | No | **Yes** | Would still need R1/R2 | Would still need R1/R2 | Would still need R1/R2 |
| Promising advantage | Mature sources, receipts, Practice, Project lesson structure | Fast truthful return with preservation | Evolving questions not fixed Stage | Real juxtaposition of competing evidence | Genuine capture-first, sparse work |
| Major risk | Disconnection/false structure | Adding strips to fragmented surfaces | Invisible curriculum of “intent” maintenance | Spatial overhead, accessibility, source duplication | Shallow linking and large-history retrieval |
| Novel backend need | None | Not assumed | Potential, **not proven necessary** | Layout state may reuse existing workspace; persistence boundary unknown | None assumed |

- **Reject A as sufficient** if repair makes R1/R2 pass yet the owner still cannot adapt a Project/Stage or relate multi-source work naturally. Reject any A implementation that adds more than a bounded, truthful preview before useful action.
- **Reject B** if a Note first requires an inquiry, generated inquiry meaning outruns user control, intent edits create more maintenance than task benefit, or a non-technical/sparse learner cannot quickly resume without a checkpoint.
- **Reject C** if selecting/rearranging more sources is harder than reading/thinking, if source editions become copies without stable receipts, if keyboard/mobile workflows are second-class, or if the board displaces ordinary Article reading.
- **Reject D** if discovery and meaningfully connected Activity/source evidence remain broken, or if large histories force repeated manual reconstruction. D still serves as the **cost/complexity floor**, not an automatic recommendation.
- **Reject all** if access rights, exact revision/anchor, interrupt/reload or honest unknowns fail. Do not choose a winner from static diagrams; try the same tasks with the user after small scripted interaction demonstrations, before a functional Workbench commission.

## Prior art: interaction mechanisms, not feature shopping

Evidence classes below are deliberately conservative. “Hands-on” applies only where an actual accessible interface was used. Official docs, even screenshots, are **not** hands-on evidence; static code is not proof of an end-to-end UX.

| Source and evidence class | Observable mechanism / transferable principle | Crucial mismatch, rejection condition or gap |
|---|---|---|
| [eLabFTW public demo](https://demo.elabftw.net/) — **direct hands-on observation**, read-only | Signed-in shared demo dashboard foregrounded recent experiments/resources; demo experiment showed Goal/Procedure/Results, status, rights and revision control. “See revisions” on this instance described max ten revisions and 100-character change threshold. A lab log can ground progress in experimental evidence and rights without a Project/Stage curriculum. | **Do not** read statuses as learner achievements or infer full history when revisions are capped. Demo is a shared configured instance; no new experiment or write trial. Relevance to non-lab reading unproven. |
| [Zotero PDF reader](https://www.zotero.org/support/pdf_reader) — **official documentation**, not hands-on | PDF highlight/annotation can enter a Note with an exact source citation; “Show on Page” returns from Note to original PDF page. A specific source → thought → source return loop is more valuable than a generic backlink. | Source-page fidelity depends on anchor/edition and permissions. Minamo HTML Article need not mimic PDF UI; implement a precise return contract, not another annotation silo. |
| [Heptabase fundamental elements](https://wiki.heptabase.com/fundamental-elements) — **official documentation**, not hands-on | Cards are canonical library objects reused across whiteboards; clicking a linked card can refocus the original, separating *source identity* from worktable layout. Useful for C and for reusable multi-context Note cards. | Whiteboard placement/curation is overhead; would need cross-view identity/revisions/rights. No paid authenticated flow tested; “better for learning” is an inference. |
| [RemNote Portals](https://help.remnote.com/en/articles/6030742-portals) — **official documentation**, not hands-on | Portal transclusion shows the same underlying text/block in another document, editable in place; this is genuine reuse rather than copying and breaking provenance. | Shared editing can surprise readers, and block-granular architecture is a large migration cost. Prefer read-only citation/link unless explicit edit context justified; avoid mandatory flashcards/graph. |
| [Capacities backlinks](https://docs.capacities.io/reference/backlinks) and [reading workflow](https://docs.capacities.io/reference/use-cases/reading-workflow) — **official documentation**, not hands-on | Explicit backlinks and unlinked mentions are distinct, backlinks can be collapsed at bottom, and reading workflow is explicitly optional (“menu, not recipe”). Capture-before-organisation and optional meaning-making should be preserved. | **Important counterexample:** copying the collapsed footer replicates Minamo's R2 discovery failure. Do not make every Note processed/tagged, or a graph appear authoritative. |
| [GitLearnOS pinned template](https://github.com/Guojiz/gitlearnos/blob/3db0bac03ff655fe7c833f941486a7db3ecde264/templates/event-record.md) — **source-code verified by prior pinned reading**, not hands-on in this audit | Event/change records distinguish state snapshots from what changed; transferable source-linked change semantics for beliefs and action history. | New event model could be much heavier than comparing existing Note revisions. No direct evidence of learner usability or deployment reliability. |
| [DeepTutor pinned consolidation code](https://github.com/HKUDS/DeepTutor/blob/1ea7df155447f4caf0e3abc86b3ff5395479cd4a/deeptutor/services/memory/consolidator/modes/update.py) — **source-code verified by prior pinned reading**, not hands-on | Snapshot/consolidation versus update/delta distinction illustrates that a corrected Note may not change identity; cache/summary invalidation must key by revision. | Opaque AI memory is not a trusted learner record. Avoid writing GPT-inferred belief changes as fact, especially with uncertain retrieval. |
| [Logseq pinned source reading](2026-10-31-prior-art-code-reading.md) — **source-code verified by prior work**, not live interface | Blocks, references and unlinked mentions highlight deliberate edge creation vs suggested contextual relevance. | Mandatory blocks/backlinks and transclusion would increase fragmentation and can convert weak suggestions into an intimidating graph. |
| [Minamo current Site V88](2026-11-01-connected-episode-ledger-and-divergent-interactions.md) — **direct hands-on observation**, plus source trace | Mature authoring/Practice/Reader flows work. The missing element is action **at relevant source** and multi-hop return, even when the graph relation exists. | Fix the failure independently of choosing A/B/C. Site-native/public-main parity was not byte-verified; avoid overclaiming exact deployed code. |

### Outside the familiar learning-tools class

Zotero's PDF annotation loop and eLabFTW's experiment log are productive counterexamples to the assumption that a central Project Workbench must organise learning. They centre respectively on *source-location fidelity* and *evidence produced while doing work*. Heptabase's multiple placements reveal a separate challenge: canonical source identity must survive workspace context. Together they argue for testing one plain capture → source → observation → return loop before adding a general knowledge graph, another AI memory layer or mandatory Stage taxonomy.

**Missing evidence and next allowable investigation:** no authenticated end-to-end Heptabase/RemNote/Capacities session, no installed runnable GitLearnOS/DeepTutor/Logseq interaction, no direct Zotero desktop test, no Minamo new persistent Activity/Note roundtrip in this audit, and no measured human preference. Treat vendor demos as selected surfaces, not comparative outcomes. A future small owner-facing screen/flow demonstration can isolate A versus C on Article return and A versus B/D on a no-checkpoint return; obtain explicit owner choice before functional implementation.
