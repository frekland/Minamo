## Verdict and best starting point

**The existing architecture supports this release with targeted read-model, navigation and UI changes. No new persistent Inquiry, CurrentConcern, evidence-board, progress or relation database is justified.** Two small shared abstractions earn their cost: a bounded read-only continuity composition service and a validated navigation-origin codec. Reuse the canonical records and existing editor/save owner.

Start by making **N01/N07 and A01/A04 fail against actual rendered links and compiled domain responses**, then repair their shared contracts before changing Home/Project presentation. In parallel within that foundation stage, characterise the indirect-Note, multi-target and older-checkpoint cases for continuity. Do not start with a new Workbench shell, generated learner summary or wholesale `workspace.tsx` refactor.

The hardest risks are: falsely complete evidence joins; confusing a browsing origin with a saved relationship; and losing exact source/task identity when native navigation, retained editions and an active Note editor meet. A fourth release risk is native Sites divergence. None currently proves a need for deeper restructuring. The [risk controls below](#risk-controls--required-implementation-and-test-gates) specify how to address each, including safe failure behavior. Failure to preserve current rights, draft/receipt integrity or exact-source return blocks release.

## Proposed contracts: view evidence, navigation and deliberate writes

These pseudotypes are **new read/view shapes and local draft intent**, not D1 tables. Keep record family names `journey`/`investigation` and stable Stage IDs internally. Do not rename persisted families to fit new UI wording.

```ts
type ExactRecord = { family: Family; id: string; rev: number; rendition?: string };
type ReadingOrigin = {
  family: Family; id: string; rendition: string;
  stageId?: string; selection?: ReadingSelection;
  // section/part-only locations also allowed, validated separately
  sectionId?: string; partId?: string;
};
type ContinuityEvidence = {
  contract: 'minamo.continuity-evidence.v1';
  asOf: string; generation: string; snapshotVersion: number;
  scope: { focus?: {family: Family; id: string}; learningSpace?: string; language?: string };
  items: Array<{
    source: ExactRecord; author: Actor; at: string; destination: string;
    basis: 'authored-writing' | 'saved-checkpoint' | 'supplied-attempt';
    preview: {text: string; complete: boolean};
    paths: Array<{edges: RecordLink[]; target?: LearningWorkTarget}>;
    checkpoint?: {id: string; revision: number; target: LearningWorkTarget;
      nextAction?: string; status: 'active'|'superseded'|'withdrawn'|'unavailable'};
    // Return existing structured claims/evidence refs, with their original basis.
    exactRead: object; detailsDeferred: boolean;
  }>;
  coverage: {
    completeWithinScope: boolean; moreAvailable: boolean; nextCursor?: string;
    checked: {targets: number; records: number};
    limits: {targets: number; identities: number; items: number; bytes: number};
    gaps: Array<'targets-deferred'|'records-deferred'|'details-deferred'|'external-unobserved'>;
    notice: string;
  };
  lastSeenByGpt: 'unknown';
};
type ViewOrigin = {
  v: 1; source?: ReadingOrigin; activity?: ReadingOrigin;
  task?: LayoutTask; project?: ProjectReturnContext;
  library?: string; practice?: string;
};
type NoteCaptureIntent = {
  // Only deliberate creation/link actions populate canonical additions.
  readingLink?: RecordLink; acceptedTaskLink?: RecordLink;
  acceptedPassage?: PassageAnchor; // existing domain-validated field
  viewOrigin?: ViewOrigin;        // local navigation only; never sent as record data
};
```

**Read composition.** Add `lib/continuity-evidence.ts: readContinuityEvidence` (proposed), called by a shared boundary dispatcher for GET/POST `/api/learning-context` and MCP `get_minamo_learning_context` using additive `scope:'evidence'` plus optional exact `focus`. Update the advertised schema/description in `domain-handler.ts`, not just the web caller. Keep existing scopes compatible; source-first UI and its continuation-specific GPT handoff use the evidence scope rather than treating legacy single-Continue output as complete. Add a narrow handoff variant beside `buildGptContextBrief`; ordinary exact passage/Note discussions keep the current bounded `get_minamo_context` request. Do not run closure on every discussion turn. No new MCP tool is necessary.

Compose existing task/rights/checkpoint readers; request exact checkpoint evidence only when needed. Reuse is not blanket certification: each traversed edge must validate scope, retained rendition and Stage membership, not merely match IDs in SQL. `eligibleLink`/Stage resolution are currently private in `project-context.ts`; extract their smallest shared eligibility helper when required, rather than copying the policy. Do not put a call back into the composer inside `getLearningContext` or `project-context`: they already import each other. Keep the composer **above** them, called from the handler, avoiding another cycle. Do not introduce a generic repository/graph framework. Legacy continuation can remain a documented compatibility suggestion, not the authority behind the new source-first UI.

For Home, select eligible authored Notes/Questions and saved Attempts/checkpoints across the requested space without requiring a Project. Article editorial timestamps are references, not learner work. For exact Project context, traverse verified Project↔Question associations and exact Stage selectors, then personal work; retain broad Project Notes and all explicit paths for multi-target Notes. Do not expand shared Articles into unrelated learners' tasks or walk reverse parent links into sibling scenario Projects. A separately selected child Project is a fresh focus; otherwise report the bounded scope.

Start with proposed bounds of **12 targets, 80 candidate identities, 20 returned items and 64 KiB response**. Record per-stream continuation state and unvisited edges in an opaque cursor scoped to owner, generation, learning scope, namespace version, focus and limits. A 409 invalidates the entire assembled page; do not mix old and new snapshots. Budget/cursor caps are partial coverage, never confident absence. Use current domain projections for every preview/path/edition, checked before returning; raw SQL is identity selection only. Do not expose denied IDs, titles, counts or path reasons. `completeWithinScope` still excludes unsaved chats/drafts and external activity. Measure query count/latency before raising limits or adding an index; avoid calling the entire journey overview once per target.

**Truthful meaning.** Deterministic output supplies dated source text and existing structured `nextAction`, facts, decisions and evidence refs. It must not use regex or text diffs to manufacture authoritative intentions, conflicts, misconceptions or closure. Keep older/newer sources available together; label ordinary prose as writing, not an agreed next action. The five questions are evidence obligations, not five generated fields or permanent dashboard panels. Optional GPT interpretation remains attributed and unsaved.

| Adversarial example | Required output, using the D3 ledger's exact records |
| --- | --- |
| Mood documentation sceptic | Provider Question r5; docs-return r1 and docs-audit r3; separate provider Stage save-b r1; checkpoint's retained research r1 **and** current research r2. Show dated candidate text and old checkpoint action separately. No Spotify capability verification, semantic winner or legacy privacy-v7 mixture. |
| Sparse Cap / calibrator Plant | Latest restart/cal-next and revised sparse/raw-series Notes open directly; no checkpoint required. Return calibration/instance status as externally unknown, with source words inspectable. Synthetic CSV/code is not physical evidence; an old failed tab is not verified lab expiry. |
| Partial or denied scope | Return only admitted source receipts. Say “More linked work may exist” when a frontier remains; inaccessible targets have no title/quote/link. Empty complete checked scope differs from empty partial scope. No “nothing happened” or denial counts. |

**Navigation.** Add one strict `lib/navigation-origin.ts` codec and use it in both native href construction and intercepted navigation. Store only validated family/ID/edition/selectors in a bounded, flat versioned query payload (proposed `origin`); allow no external URL, title, quote, owner identity or recursive return URL. Carry existing Library/Practice parsers rather than embedding arbitrary paths. Reject malformed/duplicate keys, inconsistent ranges, oversize payloads and `returnStage` without Project. Validate semantic ranges using canonical Reader/domain helpers on landing. URL is portable origin; history/session storage supplies optional scroll/focus only. A cold Note URL has no inferred originating task. An explicit later unrelated navigation clears the origin; source detours preserve it. Original Q2/P/S comes from the actual click, never the first Note backlink.

Keep source, Activity and originating task as separate fixed slots: N→X→A must not overwrite A with N or confuse A's passage with Q's Stage. No unbounded browser-stack copy. Origin priority is explicit destination context, then the current validated detour context; old session state cannot override a fresh URL. A generic link may be forged, so it conveys **no rights or relationship authority**. Render return labels from eligible fetched records only. Preserve `start/end/segments`, which several hand-written route adapters currently omit. Prefer one common href→ReadingTarget parser over another collection of field-copy handlers.

**Save and durability.** Keep one mounted NotesPanel and its current draft/flight identity; do not key it by route or move it into a new context screen. Blank capture stays unlinked. “Note about this page” deliberately accepts that displayed reading; linking its separate task remains optional. For deliberate passage capture, add a narrow Reader callback (proposed `onCaptureNote(anchor: PassageAnchor)`) using `readingCapture`, then thread the existing anchor through draft/flight/create and domain validation. Preserve it on ordinary body updates. Reuse current canonical `anchor`, never smuggle ranges into `RecordLink.reason` or add a provenance table. A route origin alone remains transient; after a cold reopen only accepted canonical links/anchor are durable. If no passage was selected, promise only the recorded edition/part, not an invented exact range.

One targeted write-contract gap is real: current `data.anchor` requires an object, and `ContentPatch` has no anchor-removal operation. For reversible accepted passage origin, propose **Note-only** `{op:'clearNoteAnchor'}` in `ContentPatch`, handled by the existing CAS/history/receipt path. Do not allow it on annotations/Flags or silently clear an anchor during prose editing. This is a small command extension, not a database migration; test retained pre-clear editions, revocation and replay. Ordinary task/reading relations already have explicit removal operations. Anchor replacement must be separately deliberate and validated, never a navigation side effect.

Existing saved Note anchors must survive edits even when no new anchor is provided. Independent writing must remain saveable if an optional link/source is unavailable: retain the draft, explain the rejected context, allow deliberate removal and a **new** payload/operation; never mutate a pending flight or silently retry as a different operation. Historical read and current-head editing stay separate, with stale-buffer comparison and receipt-readback unchanged.

## Risk controls — required implementation and test gates

**Owner follow-up, 1 November:** these controls strengthen the existing three increments; they do not add a planning phase, change 1B/2A or authorise production changes. Treat them as implementation requirements with observable failure tests, not claims that the proposed protection already works.

### R1. Incomplete evidence presented as complete continuity

- **Implement in I:** one server-owned coverage calculation for UI/MCP. A response may claim `completeWithinScope` only when its declared relationship frontier and all candidate enumeration pages are exhausted within one owner/generation/namespace snapshot. Direct-neighbor completion cannot discharge Question/Stage coverage. Keep enumeration completeness, preview/detail completeness, freshness and external unknowns separate; `moreAvailable` means pageable evidence, not every kind of uncertainty. An unknown/deferred preview must not erase its eligible source receipt.
- **Present honestly in II:** label ordering as “recent recorded work,” with source/date and a compact explanation on request. “Latest returned” is the safe description while relevant enumeration is partial. Zero checkpoints on Q does not exclude its linked Stage checkpoint; newest edit does not cancel an older intention. Keep competing source text side by side in an ordinary list. No generated “all caught up,” “no outstanding problems” or automatic correction verdict. Do not expose denied record counts/identities as coverage diagnostics.
- **Failure oracle:** put the newest relevant Note beyond a page/breadth limit, return an empty page with a cursor, insert an older Stage checkpoint, then revise/revoke a source mid-read. Assert the appropriate partial/409/unavailable result and no absolute absence claim. Extend C-MOOD/C-PARTIAL/C-EMPTY and compare HTTP/MCP receipts. Source selection is deterministic; semantic contradiction detection is not required for correctness.

### R2. Navigation history accidentally becoming a saved relationship

- **Implement in I/II:** keep `ViewOrigin` and `NoteCaptureIntent` separate types and boundary schemas. The route codec outputs navigation selectors only; the command builder explicitly allows canonical fields from a deliberate capture/link action and rejects route payload fields. No spread of URL/history objects into `WorkspaceCommand.data`, no effect that saves a relation when focus/route changes. An explicit “Note about this page” accepts its displayed source; a nearby Project/task remains an optional additional link.
- **Failure behavior:** malformed/expired origin removes the unusable return cue, with a safe way to open the current source/task independently. It does not block an unrelated blank Note or silently choose a parent. Removing a saved connection remains a separate CAS/receipt operation; changing the visible task never retargets an existing draft.
- **Failure oracle:** with clean synthetic records, run open/back/forward/reload/new-tab/search/space switches and assert no canonical relation/Note revision or command was created by navigation. During dirty writing, compare the exact pending payload and accepted links before/after every hop; a normal autosave may occur, but cannot acquire new links from the new route. N07 must return to Q2 even when Q1 is the first saved backlink.

### R3. Lost editions or passage/task origins during multi-hop navigation

- **Implement in I:** build one canonical destination from family/ID/rendition/Stage/section/part/UTF-16 segments, then use that same href for native links and intercepted clicks. Audit the concrete adapters in S6–S9/S11, including source refs from Studio, recent Notes, related-content links, search results and GPT return links. Read/validate the landing edition before applying coordinates. The source Article, Activity and originating task occupy distinct origin slots; a detour cannot replace one slot with another record's identity.
- **Failure behavior:** unavailable e1 stays unavailable with a separately labelled optional newer-edition action. Never repair offsets by matching text in e2, fall back to the current head as if it were e1, or infer an original task on a cold Note link. Restore eligible reading/focus without scrolling/remounting the independent writer. Saved exact anchors survive cold reopen; a transient original task exists only when the URL carries it.
- **Failure oracle:** A e1 containing emoji/combining characters and multiple segments → X → N → X → A, while A e2 and N r2 appear. Exercise native/new-tab, Back/Forward, reload, two linked Questions, original-Source versus display-return coordinates and denied e1. Assert exact selector equality and canonical selected bytes at each landing, not merely the presence of a Back button. Preserve the working direct Stage→Article and Practice→Activity→Article controls.

### R4. Draft, immutable-operation or native Sites disruption

- **Editor/save control in II:** retain one NotesPanel mounted under its existing owner/generation scope. Route changes may change presentation and proposed capture context, never its writer key, draft identity, undo state or frozen in-flight payload. Resolve uncertain writes using the original operation receipt; CAS conflicts retain both versions for deliberate comparison. Neither a refresh nor a newly fetched current head overwrites an independently dirty/stale editor. Preserve sections/images/media/terminal bytes and honest in-memory/local/online status.
- **Release control in III:** promote an allowlisted, hashed shared-file manifest onto an expected native HEAD, preserving native-only recovery/config/assets and the existing restricted audience/bindings. Verify native source after transfer. Test command/schema compatibility in both client/server directions; add the proposed Note-only clear operation to the existing content capability declaration. Unsupported operations must retain writing and stop blind retry. A planned rollback reconciles pending new operations first; an emergency rollback still cannot rewrite their identities or discard them.
- **Failure oracle:** committed-but-lost response, replay after later edit, 409, timeout/429/503, blocked storage, cross-tab conflict, image interruption and principal/generation change. Confirm exact text, caret/undo, attachments, command identity and canonical receipt/readback. Preserve drafts during transport failure; confirmed identity loss fences access. In an isolated release rehearsal, prove previous-version readability of new records, new-client unsupported-command behavior and native manifest mismatch rejection. Never inject these failures into live learner data.

**Freshness is part of all four controls.** Reuse `subscribeForeground`, request sequencing/abort guards and `retainContentAfterReadFailure` from [foreground-session.ts](../../lib/foreground-session.ts), alongside current permission and commit events. Revalidate the derived source list, origin labels and GPT selection after relevant Note/Question/Project/checkpoint/source changes, and on return to the tab; an external MCP edit need not produce a browser-local commit event. Scope every result to owner, generation, learning space and permission epoch. Ignore late responses from a previous scope; source/media revocation invalidates derived previews and labels even if authored `rev` is unchanged. During an unavailable refresh, retain only previously admitted eligible content with “Could not refresh”/last-checked status and Retry; a definitive access/identity failure removes/fences it. Preserve independent writing throughout. These views are checked snapshots, not real-time guarantees.

Extend `foreground-session.test.mjs`, `foreground-session-integration.test.mjs`, `reading-continuity.test.mjs` and the new contextual suites with a delayed pre-revocation response, a background MCP edit followed by focus, and a Note autosave during paging. Cap automatic stale-cursor retries and coalesce refresh bursts; continued writes may leave a visibly partial list, but must not cause an infinite restart loop or reorder the focused item under the keyboard. Record request count and cold/warm latency using synthetic IDs only; no new production learner telemetry is proposed.
