## Checkpoint 4 — bounded read-only continuity receipts (1 November 2026)

- `lib/continuity-evidence.ts` supplies additive `minamo.continuity-evidence.v1` on `scope:'evidence'`, with optional exact `journey`/`investigation` focus. `lib/domain-handler.ts` shares it across GET/POST `/api/learning-context` and `get_minamo_learning_context`, with the advertised MCP schema updated. Existing scopes and their checkpoint semantics are unchanged.
- A namespace-version/generation/owner/scope/focus/limit-scoped cursor pages a deterministic union of personal Notes, Annotations, Flags, saved Runs and Learning Developments. Limits are 12 relationship targets, 80 candidate identities per scan page, 20 returned items and a 64 KiB response envelope. Empty partial pages are not labelled complete. A changed record invalidates old cursors (409); the final namespace and generation guard rejects a mid-read change.
- Every exposed personal record is projected by the existing domain rights reader; exact authored links, retained source editions, section/part admissibility and Project→Question associations are checked before a focused path is returned. `getProjectContext` supplies its verified Question/Stage frontier rather than treating direct-context `relatedTruncated:false` as transitive completion. An older checkpoint remains a separate saved claim from newer Note prose; its pinned target edition is independently rechecked through `readRendition`. Missing editions do not silently route to current editions, nor does a revoked Question path leak its dependent Project Note.
- `lib/learning-work.ts` now exposes a narrow read-only checkpoint admission adapter using its existing evidence, retained revision and target checks. The composer distinguishes authored writing, bookmarks and supplied attempts from checkpoints, retains active/superseded/withdrawn/unavailable state, and supplies exact-read pointers rather than generating meanings or conclusions. Explicit author/date/revision and `lastSeenByGpt:'unknown'` are returned. Independent personal writing appears with no Project focus; multi-target Notes retain their separate admitted direct paths.
- `tests/contextual-continuity.test.mjs`: three new actual isolated-D1 cases for C-MOOD/C-MULTI, C-CAP/C-EMPTY-PARTIAL, C-PARTIAL/C-REV. They exercise Stage-only checkpoint plus Question-linked multi-target Note, no-checkpoint independent Note, rights isolation, HTTP/MCP parity, retained e1 after editing, trashed Question, 80 newer unrelated candidates before an older relevant Note, stale cursors, wrong focus and read-only operations. **3/3 PASS**. Adjacent six-file navigation/continuity/Project/learning-work suites **50/50 PASS**. `pnpm run typecheck` and `pnpm run build` **PASS**, with existing build chunk warnings.

**Important limits:** This is the first deterministic projection and testable API contract, **not R1 complete**. The focused Project target frontier is intentionally capped; deferred targets are explicitly marked, but no Project-target continuation cursor is yet available. Only the canonical personal-record and Development streams are enumerated, not the separate bookmark index or every specialised Activity attempt/terminal stream. There is no source-first Home/Project consumer or continuation-specific GPT handoff yet; owner C-MOOD/C-PLANT fixture replay, exact response-size/query-count benchmarking, complete denied/mid-read scenario coverage and real E1–E6 browser acceptance remain outstanding. `completeWithinScope` describes only the declared candidate scan and admitted focused relationship frontier, **not** all learner history, external execution, unsaved drafts or semantic certainty. No hosted data, Site or release operation was changed.
