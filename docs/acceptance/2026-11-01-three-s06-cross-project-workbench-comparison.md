Do not expand the corpus, migrate schema or replace the Site on the strength of these results alone.

## What differs across subjects, and what is shared

- **Different epistemic boundaries:** software source/first-party entitlement; network/lab authorisation and instance identity; physical sensor repeatability and safe low-voltage conditions. A useful Workbench must let the *source kind and verification scope* vary by subject, not force universal “progress”, “blocked”, or mastery labels.
- **Different revision problems:** Mood's scripted speaker attribution and provider-source authority; Cap's sparse logs, retracted exploit inference and uncertain expiration; Plant's idealised simulation versus physical observations and explicit drift. One generic “recent activity” feed cannot explain all three without exact earlier/current refs and an optional causal view.
- **Shared product mechanics:** old ordered Steps remain useful historical scaffolding but are poor default current focus; current concern commonly lives at Project→Question→Note; current read and UI entry need a bounded relevance/provenance projection and a transparent way to go deeper. Navigation/return-state failure is **directly observed only for Plant**.
- **What is *not* established:** missing canonical records, lost Article anchors, actual provider/lab/hardware execution, validated UI edits, or learner comprehension. Historical synthetic actor and date labels cannot turn supplied or scripted statements into server-verified external events.

## Recommended next Workbench design experiment — not executed

1. **First, a read-only projection/coverage spike** in an isolated synthetic test environment. For these three exact identities, calculate an explainable *current concern, changed decision, unresolved question, provenance and candidate next action* from scoped Project→Question→Note and relevant Note→Note links. Include exact record rev/rendition/anchor refs, authored-event/record-time distinction, actor/speaker/evidence kind, filtered/omitted count and derivation version. Golden-source tests must find the relevant latest Note(s) in **3/3**, never cross a persona/access boundary, report coverage honestly, and avoid declaring fictional commands/hardware/provider success. Measure response size, calls and whether simpler Project projection/relationship changes suffice before proposing any persistent schema.
2. **Then compare two genuinely different, plain interaction implementations** using the *same* eligible canonical slices and real existing Reader and Note draft/persistence machinery: **A:** explicit Work/Questions/Evolution perspectives with stable selection and return; **B:** one fluid contextual work surface with expandable uncertainty, evidence and decision history. They are complementary information responsibilities, not mandatory tabs or schemas. Both must preserve original Steps as reachable context while prioritising the learner's *actual current concern*. Use a reversible experimental route/flag, separate owner approval before any implementation/release, and no authoritative summary table.
3. **Run identical adversarial tasks for each design across all three histories**: Mood—reach source v5 and earliest provider-access retraction, distinguish first-party eligibility from fictional Article, preserve offline choice; Cap—find platform permission/instance uncertainty and historical HTTP correction without proposing a scan, address or spoiler; Plant—see 15%→raw-count correction, distinguish simulated hysteresis and supplied counts from measured calibration, open the pinned ADC paragraph and return to a draft. Exercise Project→Question→Note→Library→Question→Project, direct incoming links and browser back/forward; check revision/rendition/selection preservation, dirty draft, CAS conflict/reload and explicit synthetic Note receipt when separately authorised.
4. **Measure usefulness and failure, not visual preference alone:** correct current concern/evidence kind, unsupported inference count (**target zero**), exact source/revision hit rate, first meaningful action, navigation clicks/backtracks/lost return contexts, draft/content loss, keyboard/focus, and *verified* 320–390 px behaviour (not cropped desktop). Record owner/human task interpretation separately from agent browser traces. A and B can fail differently; document both.
5. **Decision gate:** favour whichever interaction supports causal understanding, evidence inspection, deliberative writing and natural resume with fewer orientation failures, while retaining the proven Question Recent work, source renditions/annotations and Notes controls. If neither can express provenance/causal links without fragile inference, bring a specific relationship/claim-level model change with migration/rollback proposal to owner review; do not assume one now. Expand to the remaining six corpus variants **only after** the three-subject slice and its safety/interaction limitations are understood and the owner approves the next gate.
