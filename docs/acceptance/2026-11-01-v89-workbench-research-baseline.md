The linked Project remained navigable, but the original contextual return route was not preserved. Reproduction: Project personal-labels Question → recent Note → supporting Library Article → Library backlink to Question. This is a demonstrated *navigation-state* weakness, not lost canonical data.
5. **Writing:** `Note on this Project`, `Note on this Question`, `Note on this passage` and existing Note editing controls were visible. Draft/autosave/CAS, refresh restoration, conflict and actual persistence were **not modified or end-to-end tested** in this read-only study.

The cloud browser session did not expose a reliable native 320–390px viewport/device-emulation control; shortcuts attempted did not yield a verifiable narrow viewport. Do **not** mark mobile acceptance complete. Earlier V88 evidence of narrow Recent Work wrapping remains historical supporting evidence, not a fresh mobile measurement.

## Retrieval finding that changes the architectural diagnosis

The canonical documentation-sceptic return Note `TEST-ONLY-m2m-docs-v1-r1-note-docs-return` is linked to its provider Question and audit Note. `get_minamo_context` for its Project returned a nine-item direct related set, `relatedTruncated:false`, but **did not include that latest return Note**. Similarly the interrupted Cap's `note-restart` is linked to the instance Question and expired Note; its Project-context direct related set omitted it with `relatedTruncated:false`. Yet exact `read_minamo_record` retrieved both, and the registered continuation selected recent Note. The issue is *which relationship closure the Project projection traverses*, not missing canonical Notes or a mere byte-limit truncation.

The weekend Project context did include its recent Note because that Note has a direct Project/Step link. The contrast suggests a bounded **Question-mediated, provenance-aware contextual read model**: include current concern sources at depth 1–2 with explicit coverage, no invented causal link and exact optional reads. Test this before inventing a new authoritative Project table or vector database.

The actor=user weekend `note-pivot` embeds lines labelled SCRIPTED GPT and SCRIPTED LEARNER. A Workbench cannot treat all text in a record as a single speaker's verified assertion. Interpretations must be labelled and excerpt-anchored, with unknowns retained, and never rewrite the underlying Note.
