What is unresolved is the *quality, relevance, hierarchy and cost* of their connection.

## Findings about the architecture, not another proposed architecture

1. **The system already has several projections of “current”.** `app/learning-home.tsx` offers Continue, history, recent genuine Notes and Favourites. `lib/project-context.ts` chooses a continuation from eligible saved checkpoints and direct Note links, preserving source and scope. `app/learning-developments.tsx` distinguishes current, history, corrections and evidence. An alternative read model should first show *exactly* what additional decision it makes that those projections cannot. Avoid adding a second authoritative summary/state store merely to power a visual concept.
2. **Scope, evidence and reversibility are strengths to preserve.** `lib/project-context.ts` has owner-scoped SQL, eligible link checks, paginated coverage and synthetic versus ordinary continuation fences. `lib/note-capture-context.ts` avoids quietly attaching a draft to an unrelated task. `lib/gpt-context.ts` bounds selected references and returns exact context. Reuse these properties regardless of interface.
3. **There is existing interaction-layout prior art *inside* Minamo.** `app/interface-workbench.tsx` supports `context-first`, `artefact-first`, `sequence` and `power` Activity presentation, responsive source/evidence panes and dev-only comparison controls. This is **not** a tested Project Workbench, but it is a component/design experiment to study before commissioning new interface experiments. See `tests/interface-workbench.test.mjs`, `tests/interface-lab*.test.mjs`, `tests/interface-browser/*`.
4. **Integration has a nontrivial change surface.** `app/workspace.tsx` coordinates routing, Reader, editing, layout, Notes and GPT, alongside domain-owned read projections. That breadth is an integration/migration risk for an ambitious redesign, **not evidence of defective code solely from file length**. A smaller navigation/interaction intervention may yield a larger benefit than replacing all these components.
5. **The existing tests are a platform, not a UX jury.** Among others: `tests/note-continuity.test.mjs`, `tests/experience-note-coordination.test.mjs`, `tests/projects-home-continuation.test.mjs`, `tests/project-context.test.mjs`, `tests/gpt-context.test.mjs`, `tests/practice-ux.test.mjs`, `tests/global-search-history.test.mjs` and browser specs. They establish intended behaviour/code contracts; no test suite can tell whether an owner enjoys using the system.
