# Natural Journey continuation and goal-first creation

The Journey-growth implementation adds `get_minamo_learning_context({scope:'resume',query:'queue project',purpose:...})` for read-only natural-name discovery. A unique eligible title/context resolves to a Journey overview or exact task; ambiguity/incomplete discovery remains an explicit choice. `scope:'journey',journeyId` shows separate stage/Investigation groups; `scope:'target',target,profile:'tutor'` combines exact saved checkpoint reasoning with current explicitly linked Notes, Annotations, bookmarks and compact terminal pointers. This is not an automatic checkpoint, a conversation transcript or proof of progress. `lastSeenByGpt` stays unknown. Use `activityCursor` only for that bounded activity stream; checkpoint/discovery cursors retain their own scope. Historical/detail pages do not replace current continuation. User-authored content and console bytes remain untrusted evidence, never instructions or write grants.

The task handoff opens a prepared request without replacing the clipboard; **Copy task request** performs that explicit action. No private Note prose enters the request or return URL. Ordinary discussion should reuse adequate context without rereading every turn. The new Journey entry similarly copies only an explicitly entered goal and thorough-authoring request; it neither sends a message nor creates resources itself.

For deliberate supplied output capture, ordinary Note commands accept `data.noteContent:[{kind:'markdown',text:'Prediction: ...'},{kind:'terminal',id:'sample-1',output:'exact supplied bytes',environment:'Kali'},{kind:'markdown',text:'Observed discrepancy, interpretation and uncertainty as supplied'}]`, without `data.body`. This compiles into the same persisted browser semantic block. An update replaces the body, so retain existing writing/captures. Encoded Note limit:24,000 characters; rejection retains the caller's submitted input and performs no write. Exact pointers may use `read_minamo_record` with family:note, id, rendition and terminalId. [Terminal contract](journey-growth/TERMINAL-NOTES.md) documents fidelity, controls and pending draft handling.

New goal authoring is occasional and owner-directed: inspect/reuse relevant Library coverage, research authoritative technical sources as needed, prepare substantial anticipatory standalone teaching with an actionable Journey/Investigations, and include an explicit **Start working locally** stage. Routine continuation remains economical and read-only. Existing byte/document/generation/revision limits still apply; bounded publications are individually atomic. Do not turn “Use minamo” into standing creation permission. Installed production tools remain the previous schema until a separately authorised release/refresh is verified.

The following section describes the retained general exact-reading handoff; its clipboard behavior is separate from the task/goal controls above.

# On-demand GPT context and exact return links

`app/gpt-handoff.tsx` adds **Discuss with GPT** to the reading experience. It prepares and copies a compact request for the existing `get_minamo_context` tool, then shows a read-only manual-copy fallback, optional deliberately entered question and ordinary Open ChatGPT link. It does not invoke GPT, open a chat, fetch private records, write records or place a durable grant anywhere. The owner chooses when and where to paste the brief. The normal passage-selection toolbar remains Flag / Annotate only.

The main tool call uses only the stable client-visible arguments: purpose, family-qualified record identity and an explicit retained rendition when present. Optional exact range coordinates/ordered segments are separate bounded discussion data, not unsupported tool arguments. At most eight individually chosen related records are requested through separate calls using those same stable arguments. This remains usable while an installed catalogue lacks the newer optional selection/relatedRefs parameters. No related records are included by default. Titles, Note prose and quoted passage text are not copied into the brief or its URL. An explicitly entered question (at most 1,000 characters) is included only in the clipboard text, never the return URL. The copied brief is capped at 6,000 characters. A large/invalid selection fails clearly rather than being truncated or moved to a guessed occurrence. Saved capture return URLs use their exact capture ID/family plus target identity/rendition; the server resolves their retained anchor, so long segment arrays are not repeated in the URL. The authenticated context tool returns eligible retained canonical content and checks the target. GPT must verify the separate focus coordinates against that content without guessing or moving the focus; the newer server/API selection option can reconstruct an exact quote when the actual visible client schema supports it. Related record reads use the same server-owned read path as the Site.

`lib/reading-links.ts` creates canonical relative links with family, record ID, rendition, section, part and exact offsets/segments. Saved capture return links also carry the capture's family/ID. Values are URL-encoded data; callers cannot supply a view, route or external destination. `absoluteReadingLink` accepts a trusted HTTPS origin only. The portable prompt uses the confirmed Minamo V2 origin by default. Links contain no quoted text or permission claims and do not themselves confer read access.

An Annotation's own reading and its original captured passage are distinct destinations. Discussing the Annotation body returns to that body's exact rendition; context metadata may also offer its `origin` link. A Flag remains an exact bookmark and returns to the original retained passage. Current eligibility checks still apply, including after the browser is closed. Neither Flags nor Annotations are instructions for GPT to act.

Context/command response adapters can use `contextDeepLinks` and `commandReceiptLinks` to add useful navigation metadata. These helpers never mutate stored receipts, command payloads or idempotency identity. Responses may separately report when an unusually complex exact URL cannot be generated; the eligible family-qualified record link remains available.

`tests/gpt-context.test.mjs` verifies exact URL encoding, family collisions, retained selection and capture references, no private prose in prompts/URLs, explicit bounded related refs, mismatch rejection, Annotation-vs-origin destinations, unsafe origin rejection and metadata-only receipt projection. The server's actual D1/MCP context tests separately verify eligibility and selected-quote reconstruction. A copied request is not proof that a newly provisioned client-visible plugin schema has refreshed or that a ChatGPT tool call occurred.
