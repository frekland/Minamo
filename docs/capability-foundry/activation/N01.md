# N01 — Exact byte and text-layout inspection

Status: RUNNABLE_STANDALONE (React specimen and actual finite-engine tests); dormant and unreleased.

Problem: a learner sees a Japanese/emoji text discrepancy and needs to compare UTF-8 bytes with the app's exact UTF-16 range coordinates. `inspectTextEncoding(source)` returns original source, UTF8 bytes, UTF16 code units and code-point spans mapping both coordinate systems. `byteRows`, strict `decodeHex`/`encodeHex` and canonical RFC4648 `decodeBase64`/`encodeBase64` provide a reusable finite inspection API.

Contract: text <=16384 UTF16 units; bytes <=65536. A lone surrogate is explicitly labelled and UTF8 replacement semantics are disclosed; no normalization or hidden repair is applied. Base64 rejects whitespace, base64url alphabet, missing padding and noncanonical pad bits. This is encoding, not encryption. The viewer is a runnable React specimen, not persisted canonical metadata.
