# MCP learning and resource quality evidence

This records PR26 implementation and isolated synthetic Worker/MCP/D1 checks. Production deployment, installed discovery and production timings belong to the final release receipt. No private learner checkpoint text, identities or source content are fixtures here.

## Material choices

- Exact-target `get_minamo_learning_context` MCP reads now default to a focused tutor response using the existing input shape. HTTP/UI reads remain compatible full history; `profile:full` and focused `developmentId` reads retain detailed access. The current exact canonical stage, its authored intent/outcome/checkpoint, next-stage destination, latest checkpoint view, older eligible checkpoints and explicit related targets arrive together. Broad links never manufacture checkpoint membership or change a primary target. Explicit per-event relevance works in both Stage/Investigation directions.
- Optional typed `decisions` retain choice, **reason**, provisional/established choice status, honest evidence basis and exact references. `nextAction` preserves an agreed practical action independently of open questions. Established means an agreed choice, never mastery. Existing facts/checkpoints remain unchanged. Small checkpoints need only `summary`; kind and empty facts/questions have deterministic defaults. Intent, exact target revision, generation, operation identity and evidence guards remain compulsory.
- The shared Site/MCP resume projection shows the latest eligible checkpoint rather than inventing a semantic synthesis. Older eligible rationale is explicitly prior context. An unavailable latest checkpoint does not resurrect an older one as current authority. Recorded/current revision and rendition are compared so tutors can distinguish historical next questions from a subsequently revised route.
- Canonical reading parts are returned whole. Focused task reading has a 16,000 serialized-character part budget; each of at most four explicitly related tasks has 4,000. Oversized parts are deferred with exact section/part identities and a full-reading route. These are reading budgets, **not a claim of a strict total token cap**: bounded substantive checkpoints may legitimately be larger.
- Mechanical context assembly, defaults, identity resolution, exact-revision reference enrichment and permission checking moved/stay server-side. Educational interpretation, provisional decisions, exercises and whether an explicitly requested checkpoint warrants a particular statement remain GPT judgement. The response's tutor guidance is trusted application guidance; saved facts remain evidence/data, not instructions. No automatic checkpoint/session or paid inference was introduced.

## Comparison on the same safe fixture

The pre-change measurement used a synthetic 15-stage Journey, one exact Stage checkpoint and one explicitly related Investigation, through the actual local MCP/Worker/D1 path. The fixture checkpoint contains a provisional rationale, reported attempt, misconception and next question. It is not imported learner data.

| Path | Pre-change response bytes | Post-change response bytes | Quality difference |
|---|---:|---:|---|
| `get_minamo_context` with exact stage | 17,739 | 21,930 | Detailed path still retains whole-route reading; new current-task/resume information makes this deliberately more detailed, not the lean tutoring default. |
| `get_minamo_learning_context` with existing exact-target arguments | 2,211 | 5,298 | Adds the actual task, faithful latest checkpoint view, related question, explicit provenance/revision distinction and checkpoint guide; avoids fetching the whole Journey to obtain the task. |

For the representative task+continuity workload, the focused response is about **71% smaller** than the old whole-route context while preserving the relevant checkpoint and supplying the task. Both can use one read when the exact target is already known; this does not claim a universal call-count reduction. The old bare-learning response was smaller precisely because it did not contain the task or a foregrounded continuity view.

Observed one-sample elapsed local calls were 18.65 ms / 8.46 ms before and 25.15 ms / 16.65 ms after for detailed/focused paths. These short local measurements are noisy, include fixture dispatch/serialization, and **do not establish a latency improvement**. Added safe projection has some cost. Production end-to-end plugin/tool latency must be measured separately. Response bytes exclude the surrounding host tool envelope; token counts were not measured.

A richer two-checkpoint regression trace preserves an older provisional choice/reason when the newest checkpoint records a later attempted task and misconception. Its focused response was 5,740 bytes versus 23,177 bytes for the detailed path, one focused round trip and no schema retry. This illustrates bounded continuity fidelity, not model-wide tutoring reliability.

## Resource creation, revision, indexing and reuse

See [manuscript evidence](MANUSCRIPT-METADATA-EVIDENCE.md). The real isolated MCP/D1 lifecycle creates a reusable subject Area, technically substantive Article, practical Journey and open Investigation in one guarded publish without a mandatory preview. It includes JavaScript examples, a native diagram, purposeful local relationships, Area membership and an indexed exact alias. Same-identity Article and Investigation revisions retain old readings/source editions and guards; a separate Journey reuses the Article. These are educational resources, not learner achievement records.

Rich explicit stage labels/list items/subheadings now compile into intended metadata without requiring a second metadata patch. Conflicts and oversized labels produce diagnostics rather than guessed meanings. Investigation reuse/revision is admitted consistently through manuscript, schema and editorial coverage contracts, under the existing same-role explicit target and CAS rules. No title matching or weakened source-use approval was added.

### Normal future owner/GPT authoring, beyond this commission's content edits

The normal tools now explicitly guide **future** reusable resource creation. `get_minamo_editorial_policy` lazily supplies role-specific educational guidance, an executable original connected Area/Article/Journey/Investigation example, compact catalogue/Area/reference declarations, exact reuse/revision shapes and optional diagram/media syntax. Its worked Article explains a mechanism, code prediction and a missing-return pitfall, with an authoritative link and indexed terminology; it is a shape example, not content automatically written into the owner's Library. Ordinary tutoring does not fetch this guide repeatedly. The publish description foregrounds resource substance and discoverable catalogue intent rather than only storage/safety mechanics.

Structural author feedback now identifies a Library reference without explanatory prose, a code section without explanation, an exact copied Journey section, and repeated administrative/tutoring scaffolding. Findings include **document key, path, advisory severity and repair guidance**. Unsupported rich syntax remains visible with its warning. The old character-count `sparse_explanation` warning was removed: a concise conceptual reference can publish directly without code, media, fixed headings or a length quota. These signals cannot establish factual correctness or certify teaching quality; GPT must review semantics and usefulness.

The optional manuscript preview is compact by default; `detail:true` deliberately returns full proposed canonical records and source maps for rendering. In an actual equivalent local MCP fixture, the detailed response reproducing the previous always-detailed preview was **12,586 bytes**, versus **3,485 bytes** for the compact response (**72.3% less**) with identical record refs and warnings. This changes response overhead, not the original source or saved richness. Single local timing pairs varied and do not support a hosted-speed claim. Redundant per-Article candidate searches formerly overwritten by the manuscript-wide candidate pass were also removed; direct structured-package discovery is unchanged.

`tests/future-authoring-guidance.test.mjs` retrieves the normal guide and publishes its original connected resource set through the actual MCP/D1 path: one optional guidance read, **one direct publication**, four connected records, a worked JavaScript example, troubleshooting explanation, source link, Area membership and exact alias index, with no internal block IDs or schema retries. `tests/pr26-independent-authoring.test.mjs` independently authors a different process/working-directory explanation, then creates, discovers an exact command, revises while preserving section/example identity, retains Area membership, reads history and reuses it from a second route without duplicating the Article. Its thin-code diagnostic and concise-concept control verify proportionate feedback. These are normal future authoring workflows, separate from bespoke edits to existing Mood-to-Music records.

The richer guide is a larger optional authoring response (roughly 10 KB in the synthetic trace). This is an intentional lazy setup cost for useful examples and discoverability, not overhead added to live tutoring reads. No additional preview or editorial approval step was imposed on ordinary direct publication. Existing capabilities for rich source/indexing/reuse were retained and made easier to discover and check; the server does not automatically invent pedagogical depth, semantic connections or supporting media.

## Integrity and challenge corrections

`tests/mcp-learning-quality.test.mjs`, `tests/learning-work.test.mjs` and `tests/recovery-learning-catalogue.test.mjs` exercise actual local domain paths: read-only use, minimal and legacy checkpoints, provisional reasons, exact targeting, related context, corrections, stale revisions, evidence revocation, bounded details, generation/history and recovery. Existing repeated-evidence checks remain within their actual D1 query budgets (34 write / 33 full-context prepared statements in this run).

Independent challenge found that new decision evidence also needed exact rendition enrichment when callers supply an exact revision without a rendition. This was corrected and tested against a Note changing from revision 1 to 2. Cross-target review also corrected the revision comparison to use the checkpoint’s primary target rather than a related target’s unrelated revision. A separate review of recovery found that the new decision/next-action fields needed the same permission redaction as older facts/summary: source revocation now suppresses them in exported current/history/receipt paths, and the recovery round-trip test covers the new fields before and after revocation.

The independent tutor continuation uses a separate safe focused response, not production learner data. Its assessment belongs to the independent integration report. One grounded continuation is evidence of availability/use in that example, not deterministic proof that every future GPT conversation will behave identically. Physical Android and production installed-client verification are outside these local tests.
