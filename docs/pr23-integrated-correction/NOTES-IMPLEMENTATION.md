# Rich Notes and calm autosave — implementation evidence

The V19 composer was a Markdown source editor with formatting-shaped buttons and a separate preview. V1's useful lesson was semantic composition with one undo history; its legacy DOM/application architecture was not copied. V2 now uses ProseMirror's established Markdown schema and history for live headings, nested lists, emphasis, quotes, links and private image nodes, with an embedded CodeMirror 6 NodeView for JavaScript/TypeScript, Python and SQL code. Code edits are ProseMirror transactions, so writing, formatting, code and inserted image nodes share a Note's undo history. Each open Note retains independent state, selection and source memory. The existing window/tab/dock/resize controller and private asset staging/attachment path remain in charge.

Persistence stays `markdown-v1`, with original source left untouched on open. The editor does not load external Markdown image URLs: external image syntax is displayed as a source placeholder. Private image nodes contain the existing typed part identity and display authenticated `/api/assets/` URLs or browser-local object URLs. Upload still requires a description and deliberate private insertion, and uses the existing idempotent staging upload identity. Removing/replacing/moving an inserted image is an undoable document edit.

Lossless compatibility takes precedence over silent migration. Legacy tables, task lists, strikethrough, complex code fences and mixed line endings choose an explicitly explained original-source editor; a canonical-visible-text comparison catches additional incompatible conversions. Uniform CRLF/CR code and text line endings are retained through rich edits. Bare-language code is always fenced rather than emitted as unsupported indented code. Existing canonical Note parsing and historical rendition semantics are unchanged. A new standalone backtick fence inside a rich code block is rejected before saving and its attempted source is shown for copying; the last supported Note remains retained. These are bounded format limitations, not an implicit migration of the old corpus.

Every change still enters owner-scoped local draft storage immediately. Remote autosave now waits for a 650 ms writing pause, bounded at four seconds during continuous input. It flushes opportunistically on background/blur, without promising an acknowledgement during page shutdown. The header stays “Autosave on” during healthy writing; exact retained/saved/operation messages remain available in its tooltip, and conflict, unavailable local retention and unacknowledged operations retain prominent attention/recovery controls. CAS, exact operation replay, uncertain-outcome checks and saved-versus-local comparison are unchanged.

Independent review caught two migration hazards and a lifecycle edge: default CommonMark serialization could emit bare code as indentation; unsupported old constructs needed a safe source fallback; same-identity fallback needed to destroy the detached rich view before reopening another Note. These were corrected. Implementation review also prevented nested CodeMirror dispatch when forwarding its own edit and prevented serialized trailing-empty-paragraph differences from resetting live selection/history.

Automated evidence: `tests/note-rich-writing.test.mjs` adds fourteen checks covering rich semantic round-trip, nested formatting, Unicode code, image identities/literal marker-looking code, external image source treatment, source compatibility guards, uniform CRLF, bare code fences, actual ProseMirror undo/redo and independent histories, autosave timing and preserved newer-writing/conflict acknowledgement. Together with the pre-existing Note writing/continuity suite, 36 tests passed in the focused run. These are synthetic automated tests, not physical Android or authenticated hosted image-upload evidence. Root integration records actual rendered/browser acceptance separately.

References used for implementation: official [ProseMirror reference](https://prosemirror.net/docs/ref/), [Markdown example](https://prosemirror.net/examples/markdown/) and [embedded CodeMirror example](https://prosemirror.net/examples/codemirror/) retrieved through Context7; V1 `app/editor.mjs` read-only historical reference. Dependencies are regular editor libraries, with no inference service or additional hosting infrastructure.

Further rendered review corrected the code token contrast to the reader's accessible dark palette and preserved rejected/uncertain-save explanations during subsequent typing; new-Note menu choices gained explicit accessible labels. The draft remained locally retained. The browser save command now uses the shared `noteSaveCommand` factory: new ordinary Notes declare `false`, while existing Note updates omit classification and preserve the saved value. The safeguard itself is unchanged. `tests/note-save-provenance.test.mjs` executes the exact browser factory through real isolated local D1 for both classifications, successful body updates, exact replay, stale CAS rejection, attempted reclassification rejection and normal browser creation. Typecheck and all 37 focused Note tests passed after this correction. This subtask made no hosted record writes; root owns the subsequent browser recovery/readback receipt.
