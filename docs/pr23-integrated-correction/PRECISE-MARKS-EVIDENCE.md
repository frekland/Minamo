# Exact marks and passive selection

PR26 changes `app/reader.tsx` and `app/reading-interactions.css` so the saved UTF-16 text range itself is the control. Flags use a discreet dotted underline; annotations retain their background; an overlapping segment carries both states and both exact record IDs. Click/tap, or keyboard Enter/Space on a focused marked range, opens the existing individual mark chooser and revision-safe annotation/Flag actions. No trailing per-paragraph icons or saved counts remain. Keyboard focus returns to the precise marked range when a preview closes.

The previous pointer-start handler unconditionally removed the dismissed-selection guard. A passive pointer sequence could therefore re-admit the unchanged native selection. Dismissal now retains its exact rendition/range identity while that native selection remains present; a passive tap which dismisses a selection also records that identity. Opening/closing a saved-mark preview clears the obsolete native range. Deliberate new range selection still passes through the existing canonical text, Unicode, source-permission and rendition validators. An outside tap closes a preview without returning focus over the learner's next gesture. This is a targeted state correction, not a replacement of Android native selection.

The unwanted Reading options disclosure, GPT handoff and administrative revision/provenance chrome have been removed from ordinary Reader headers. The existing Favourite control remains compact. The whole-passage select remains available after the reading for keyboard/touch users who cannot drag a range. Historical-edition and unavailable-source warnings are retained because they affect the validity of the displayed evidence.

C18 follows the legitimate evidence route: saved learning is a revisioned Development, not a canonical reading-family record. Learning UI should link its exact underlying eligible evidence into Reader for marking, and retain explicit checkpoint correction for reported-only material. Transient derived summaries do not receive guessed Reader anchors.

Focused verification: 39 tests pass across reading interactions, anchor identity, source excerpts, rich Reader and PR24 code Reader. Added assertions verify exact-word keyboard controls, combined overlap state/IDs, no paragraph-end markers, no Reading options, and retained non-drag selection access. Existing tests retain repeated-text occurrence, CRLF/tabs/astral/combining UTF-16 identity, source-origin mapping/revocation and old-edition behaviour. These are automated source/render tests, not physical Android gesture acceptance. Managed browser QA was attempted by the coordinating agent but blocked by the tool URL policy after preview repair; no alternate browser surface was used. Actual browser gestures and physical Android acceptance remain unverified. Added state-sequence regression covers the retained native range after a passive tap, preserving suppression through further taps, allowing a changed range and deliberately reselecting the same words after genuine collapse.
