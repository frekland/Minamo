# Explicit manuscript stage metadata — PR26

The V19 compiler already preserved rich Markdown and generated canonical records atomically. Its stage metadata projection only recognised a whole paragraph beginning `Intent:`, `Outcome:` or `Checkpoint:`. Natural authored list declarations, several soft-line declarations in one paragraph, and labelled subheadings could remain visible in reading while their navigation/context metadata disappeared.

`lib/manuscript.ts` now projects explicit labels from ordinary/rich paragraphs, list items and `### Intent`/`### Outcome`/`### Checkpoint` followed immediately by their paragraph. It does not invent educational intent from prose. Code and quotations do not declare metadata. Conflicting declarations omit the ambiguous field with an advisory; oversized values retain the complete canonical reading and original source instead of truncating. Missing metadata and question-shaped outcomes remain advisory quality signals, not a pedagogy certificate or publication gate.

The same safe synthetic 677-byte request was compiled before and after the change. It contains a list with bold Intent/Outcome labels, a Checkpoint subheading and a small JavaScript example. The original compiler returned zero of the three authored fields. The amended compiler returns all three. The internal package grows from 1,651 to 1,800 bytes because it now retains those authored fields. No additional request fields, calls or schema retries are needed. One cold local timing was 13.9 ms before and 33.1 ms after; a post-change test run measured 28.7 ms. These single-process timings are noisy and are not a latency improvement claim, hosted measurement or token count.

Focused verification: `node --test tests/manuscript-metadata.test.mjs tests/manuscript-independent-review.test.mjs tests/manuscript-identity.test.mjs tests/manuscript-introduction.test.mjs` — **10 passed**. Coverage includes rich/list/multiline/heading declarations, retained exact source and code, no inference from code/quotes, conflict/oversize warnings, ordinary insertion/reorder/rename identity, explicit stage reference links, and legacy rich introduction/stage checkpoint retention. These are synthetic/local tests, not installed-client acceptance.

## Future normal authoring improvements

The future GPT/MCP authoring path now receives structural quality signals, rather than a generic minimum-character warning: `reference_without_explanation`, `code_without_explanation`, `reference_only_tutoring_scaffold`, `reference_repeats_journey_section` and `repeated_tutoring_scaffold`. Each signal identifies the document, canonical path, advisory status and concrete remediation. The compiler tracks actual paragraph source separately from headings, so a concise or fully emphasised explanation is not mistaken for missing prose. Exact repetition and recognised administrative scaffolding are risk signals only; Minamo neither decides semantic equivalence nor mandates code, diagrams, media or a word count. Original source and canonical reading remain intact.

Manuscript preview now defaults to compact exact refs, warnings and coverage candidates. `detail:true` deliberately returns full canonical proposed records and the source map for rendered review. That flag does not alter publication identity or immutable source; replaying an otherwise identical publication with the preview hint remains idempotent. Existing full-detail rendering tests now request it explicitly. Publication receipts retain their established compatible shape.

Actual equivalent local MCP preview requests for the rich four-record fixture returned **3,485 bytes compact versus 12,586 bytes full detail**, a **72.3% response reduction** with identical proposed refs and warning content. Both are read-only and leave no source edition or records. A repeat pair measured 39.3 ms compact and 51.3 ms full detail, but these single local observations are not a hosted speed claim or a token estimate. The complete fixture now includes explicit quality-risk preview, full-vs-compact comparison and publication replay, so its total inspection trace is **18 calls**; ordinary publication remains one call.

Latest combined focused run (metadata, rich workflow, catalogue, publication, endpoints, independent compiler review, identity and introduction): **36 passed, 0 failed**. The rich normal create/revise/index/reuse/source workflow remains substantive, with the Article's original examples and diagrams preserved and only one independent Article identity after reuse.
