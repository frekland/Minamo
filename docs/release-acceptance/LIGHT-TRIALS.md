## Friction found and corrected

1. **Stale activation dossier:** it instructed `enabled:false` → `true`, although both banked views were already enabled. `LIGHT-ACTIVATION.md` now states the actual state and requires inspection before any edit. This prevents redundant frontend churn.
2. **Catalogue/module location:** a permitted dossier lookup suggested absent `lib/mcp.ts`; current Activity tools live in `lib/activity/mcp.ts`. The dossier now names the exact path and MCP envelope check/parse sequence.
3. **Two independent reserved-table mistakes:** both first producer agents attempted to inspect protected Cloudflare `_cf_` metadata and received `SQLITE_AUTH`. Their trial-only observations were narrowed to accessible application tables; no storage/security rule was weakened. The dossier now names this boundary.
4. **Immutable recipe:** the bytes trial initially tried to mutate a frozen admitted slot. Copying the recipe and mapping slots, as the SDK requires, resolved it. No app change or dependency was necessary.
5. **CAS receipt interpretation:** the typed Attempt trial initially expected a stale-write MCP transport error. The real domain correctly returned a successful transport envelope with `receipt.status:"conflict"` and no record. Both SDK dossiers now require inspecting `receipt.status` for writes; `isError:false` alone is not a committed save.
6. **Per-kind catalogue ergonomics:** advertised kind names are not complete payload schemas. The Japanese trial required allowed source-schema inspection. `SDK-RECIPES.md` now links the exact tested original ruby+TeX request, UTF-16/canonical/hash rules and executable regression, and labels the broader schema-discovery limitation. It does not promise catalogue-only authoring for every engine.

The safe finite-view task generated only a three-line factory delegation, one server metadata entry and one trusted loader entry. Before registration its exact fixture failed on unknown `viewId`; after registration it validated and persisted/read back exactly. Its finite controls, full textual alternative, source-denial and exactly-once cleanup ran in a native-DOM harness. The original omitted-view React renderer could not mount in that minimal harness; the corrected test proves original-loader selection through an explicit sentinel and labels the remaining browser proof separately. The optional trial registration is kept solely as a patch and fixture. Run `node docs/release-acceptance/fixtures/replay-finite.mjs` from the candidate to clone current local source into temporary storage, apply that patch, execute the three tests and remove the clone without changing release source.

Two discovery-only workerd startup attempts in the fourth agent stalled; their own processes were terminated without source/network-setting changes. The bounded executable test then initialized normally and passed, as did the coordinator’s separate current-candidate run. The stall is retained as environment uncertainty rather than an inferred application defect.

All initial errors/retries remain in the individual reports. None is relabelled a product correction where only trial code was wrong.
